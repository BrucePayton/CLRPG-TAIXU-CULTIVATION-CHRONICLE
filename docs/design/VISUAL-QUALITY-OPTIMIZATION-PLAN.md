# 太虚修行录：地图与角色品质优化计划 v1

日期：2026-10-04

状态：待确认的实施计划；本文不代表美术制作、代码修改或实机验收已经完成。

## 1. 目标与依据

以现有落星台 Boss 战、持玉剑主角及旧战斗特效为视觉基线，使新增地图和 NPC 在构图、比例、像素密度、动作和声音上形成一致体验。先完成一个可实际游玩的高质量样板，再扩量。

依据：

- [研究记录](RESEARCH-V1.md)：复用此前本地 WeKnora 与参考项目研究；本轮未重新查询知识库。新增世界观或机制时，再针对缺口补查并记录来源。
- [原策划](GAME-DESIGN-V1.md)：保留地图职责、遭遇战、任务与术式方向。
- [P1 技术交付](P1-DELIVERY.md)：作为当前功能状态依据；原策划第 8 节是更早的历史状态，不作为最新交付结论。
- 本轮代码与原图诊断：新增地图仍沿用狭长分区；医师带装饰框，建筑包含多物件；自动去底和缩放不能替代资产清理；新角色动作不足。

本计划调整原 P2–P5 的执行顺序：**视觉样板前置，暂缓新增支区和大规模玩法扩展**。旧文档保留为历史，不改写其验收记录。

## 2. 不变约束与暂缓范围

- 保持浏览器 Canvas 运行时，不迁移引擎；Blender 只辅助资产与构图。
- 保持复古像素、2.5D 俯视，不恢复统一 32×32 限制；保持当前 480×270 逻辑视口作为首轮比较基准。
- 保持传统 RPG 现场出口跳图，遭遇战在当前地图发生；落星台是独立地点，切磋不成为必经门槛。
- 保留主角身份、玉剑、Boss 独立形象、云海圆台与前后景立柱。
- 保留闪身残影、剑弧、御剑拖尾、持续护身、符火及 Boss 既有招式；不借美术调整擅自重平衡飞行消耗或战斗数值。
- 暂缓新支区、完整关系系统、多傀儡、更多融合组合和硬件光追。现有光照只做适配、可读性与性能检查。
- 本计划不授权提交、推送、发布或上传私人素材；音乐可本地试听，不因代码采用 MIT 就视为音乐可公开分发。

## 4. 分阶段实施

### V0：冻结基线与制定美术规格

工作：

1. 记录当前代码、运行时素材哈希与本地变更状态，保留可恢复副本；不覆盖现有未提交工作。
2. 留存落星台交谈、切磋、闪身、护身、御剑的真实运行画面；留存听雨驿当前画面作前后对照。
3. 建立风格板：旧主角、Boss、圆台的形体、明暗、配色与像素簇；区分参考原画和实际游戏显示效果。
4. 冻结尺寸初案：主角现有约 51 逻辑像素高为标尺；成人 NPC 身体约 46–54，Boss 维持现有约 76。数字是首轮目标，不含装饰框、投影或特效。
5. 校准同一地面投影、脚底锚点、建筑落地点和光向；不把现有椭圆压缩比直接当成 Blender 相机角度。
6. 做深色、浅色、旧圆台三种背景的角色可读性样板；采用统一基础色板和局部强调色，不简单对所有对象一刀切限色。

交付：风格规格、回归清单、基线截图与首批资产卡。

通过条件：参考与目标显示尺寸明确，旧内容可以复现；开始新素材制作前，不再依靠泛化的“精美像素风”提示词代替规格。

### V1：听雨驿＋医师 NPC 高质量样板

**首轮只做这一张地图和一个 NPC，不同时铺开全部地图。**

场景：

- 药庐、庭院、药圃和通往雾松林的出口组成清晰空间；药庐作为地标，院中留出交谈、试法和御剑空间。
- 建立前景树冠/屋檐、中景人物与建筑、地面路径、远景或边界植被的分层；避免用高亮细碎地面抢走人物注意力。
- 地图先以约 2×2 个视口的可达白盒试布局，再按走图结果定尺寸；不直接扩大原竖条坐标，也不承诺必须填满该面积。
- 建筑拆分基座、主体、屋顶和独立道具；物理碰撞以落地体积为准，人物到屋后时有可读的遮挡处理。
- 草地/道路先做至少三种基础变体及必要的边、角过渡；河岸、高差留给对应地图，不一次制作全套无用地块。
- 适量药架、灯笼、石阶、晾药盘讲清药庐用途；装饰不能堵出口或遮交互目标。

医师：

- 去除竹叶框、背景、原图投影和无关物件；若修整成本过高，基于风格参考重新生成候选。
- 明确服装、药囊与身份轮廓，避免直接换色复用主角。
- 首批四方向：每方向待机 2 帧、行走 4 帧，共 24 帧；另做一个面向的辨药/调息 4 帧。帧数是制作预算，不以帧数替代动作质量。
- 先通过一个方向的完整动作循环再扩方向；左右翻转仅用于不破坏持物、服饰不对称性的场合。
- 动画速度与位移、停步匹配；脚底稳定，腿部交替，持物不漂移，头身不跳变。

接入：

- 运行时消费已清理的透明 PNG/图集与元数据，不继续依赖粗略去底承担最终清稿。
- 候选目录与实际使用清单分离；缺失或失败时使用明确的回退资产，不悄悄加载最新候选。
- 保留旧素材映射以便局部回退；样板之外的地图不一并替换。

通过条件：实际游戏尺寸下没有边框、白底、杂物、明显滑步；构图与角色比例协调；用户审阅样板方向后才批量扩展。未获得审阅时保持候选，不记录为用户批准。

### V2：按地图职责逐张扩展

| 顺序 | 地图 | 视觉重点 | 同步验证的现有交互 |
| --- | --- | --- | --- |
| 1 | 雾松林 | 松林疏密、兽径、倒木、巢区边界；苔角鹿作为首个魔兽动作样板 | 观察、采集、警觉/逃离与遭遇战可读性 |
| 2 | 照石溪 | 扩宽独立地图构图，河岸过渡、桥面、浅滩与水面层次 | 桥梁通行、御剑、出口安全；环境术式先保留设计接口 |
| 3 | 残星原 | 残碑、破损星盘、山门与台阶，形成通往旧圆台的视觉过渡 | 读碑、探索、返回路线 |
| 回归 | 落星台 | 保留旧构图与主体资产，只修共用渲染产生的问题 | 交谈、拒绝、切磋、离场、重赛与旧特效 |

魔兽按鹿→豕→狼制作：分别表现进食/抬头/逃离、扒地示警/冲撞、警戒/移动/攻击与撤退；依据实际状态机绑定动作，不以文字提示冒充行为。

地图数据逐步从旧全局图册过渡到明确 mapId 与地图内坐标；同步迁移出口、出生点、实体、碰撞、小地图与任务位置。稳定 ID 和跨图事实不得丢失，不新增按横坐标猜地图的依赖。

通过条件：一图一验收，走完双向出口与核心路径，地标独特，角色比例一致；再进入下一图。地图重构不能重置采集、敌人状态或奖励。

### V3：战斗表现与音频一致性

- 在驿站、森林、溪边和落星台回归同一套玉剑、闪身、飞行、护身和融合术式；检查昼暗差异下的轮廓。
- 分清地面预警、人物、弹体、前景与屏幕光效；屋檐、烟雾、树冠不能吞掉关键危险提示，提示与真实判定对齐。
- 保留旧 Boss 招式节奏与辨识度；不靠增加粒子密度掩盖角色、地形问题。
- 为现有光照建立开/关对照与性能预算；如调整算法，准确标注为 2D 光照/阴影，不宣称硬件光追。
- 从用户本地音乐中每类挑少量候选：驿站安定、森林疏朗、溪流空灵、遗址克制、圆台交谈/切磋分段。逐曲 A/B 试听后定稿。
- 试听完整曲段与至少三轮循环，检查切图淡化、短遭遇重复起奏、技能被背景音乐掩盖等问题。
- SoundGenerated 仅补试听确认缺失的剑风、闪身、命中、机关音；记录真实生成/裁切来源。未确认再分发权利的音乐留在本地。

通过条件：旧技能没有表现退化或数值变化；战斗危险可读；音频记录区分技术播放通过与主观风格确认。

### V4：恢复玩法扩展并完成整体回归

- 视觉样板扩展稳定后，再落实原策划“药香引路”：观察采集→材料补救→炼丹→救助→可见回访变化。
- 然后安排两种环境术式、三节点阵法、单傀儡，最后进入新支区与成年角色自愿合修。每项单独定义规则、表现和测试，不与此次美术修复捆成大版本。
- 20–30 分钟任务体验是后续实测目标，不宣称当前已有该内容时长。
- 形成完整交付记录，分别标注已完成、技术通过、视觉待审、暂缓和已知缺陷。

## 5. 资产制作与记录规则

推荐链路：需求卡 → 必要时 Blender 体块/姿态参考 → ComfyUI 小批候选 → Aseprite 清稿/动作 → PNG＋元数据 → 游戏比例检查 → 实机验收。

- Blender：固定正交参考相机，校准建筑、坡道、遮挡与人物比例；保留使用到的 `.blend`。不强制每个小物件都走 3D 流程。
- ComfyUI：先确认当前可用模型与参考约束节点；使用旧场景参考统一风格，避免白底/品红底、俯视/三分之四视角等互相冲突的提示。每轮建议 2–4 个候选；连续两轮同类失败先调整约束，不盲目扩量。
- Aseprite：处理透明边缘、像素簇、色板、轮廓、枢轴与连续动画；保留 `.aseprite`。自动缩小、限色或导出成功不算清稿完成。
- 每个资产记录 ID、用途、模型/工作流版本、种子、参考来源、源文件、输出哈希、原始/显示尺寸、锚点、帧时长、运行时映射、许可和检查证据。
- 沿用已有制作记录中的 `generated_candidate`、`visual_review` 等字段语义，不另建脱节状态机；技术检查、人工审阅和用户方向确认分别记录。
- 生成服务仅在开发时使用，交付游戏离线读取静态资产。工具不可用时明确记录阻塞，继续可独立开展的布局/规格工作，不假称完成清稿或生成。

## 6. 验收清单与停止条件

### 视觉

- 游戏原生尺寸、整数放大和实际窗口各检查一次；禁止只拿放大的原画验收。
- 透明素材在深/浅底检查，含腿间、树根、屋檐；无非设计底色和边框，无整张集合缩成单体。
- 角色身体尺寸、脚底和阴影一致；停步不滑动，移动不只有贴图平移；建筑、树木与角色透视协调。
- 每图有明确地标、可读出口与行走空间；地面接缝、重复纹理不突出；遮挡不阻断操作信息。
- 比较基线与新版本的同一技能和同一观察尺度；保存真实游戏截图/录像，原图与工作流截图仅作制作证据。

### 功能与性能

- 每批接入执行 `npm test`、`npm run build`，按缺陷补测试；文档阶段不冒称已执行。
- 八个出口覆盖双向跳转与重复输入，规则级 20 轮往返；另安排正常入口实机走图，两类结果分别记录。
- 验证资源、护身、飞行、采集、敌人状态与奖励保持；没有跨图伤害、穿边界跳图或出生卡住。
- 30/60/120 FPS 条件下测试资源与规则一致，暂停不偷跑；不能测试的条件明确标注。
- 在同一台测试设备、相同窗口和操作路径上记录场景帧耗时、峰值及粒子数量。暂以 60 FPS、P95 帧耗时不高于 16.7 ms 为目标；若基线已不满足，先测量再确定优化预算，不虚报达标。
- 离线资产无缺失；缺失资产回退不破坏玩法，错误可追踪。

### 停止批量扩展的条件

出现候选未清理、角色身份漂移、明显滑步、关键预警被遮挡、旧 Boss 场景退化或跨图状态丢失时，停止该批扩量并修复。样板审阅未确认时，不擅自将方向标为批准。
